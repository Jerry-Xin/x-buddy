## Calculation API

- `cron(expr, tz, jobId, widthMs?, exact?)` validates through exact
  **croner 10.0.1** and retains the resolved width. Timezone is mandatory.
  Recurring top-of-hour defaults resolve to 300000 ms; fixed daily 09:00 and
  exact resolve to zero. Explicit widths must be integer 0..300000. Only the
  first four SHA256 bytes, read as uint32BE, determine the offset;
  `j7f3k2q` / 300000 gives **253353 ms**.
- `next(schedule, nowMs)` is strict. `previousOrBefore(schedule, nowMs)` includes
  an effective slot exactly at now. Cron combines pinned raw normalization with
  the pinned four-probe stagger arithmetic. `dueAt` applies activation/watermark
  fences to the effective slot; occurrence IDs use it too. Raw exports are
  diagnostic/fixture seams, never substitutes for recovery slots.
- Gaps are skipped. Repeated hours run once at the first occurrence, including
  Lord Howe's half-hour repeat. Nonexistent year-limited reminders never spill.
  DOM/DOW OR, `+` AND, five/six fields and pinned year syntax use Croner.
- `parseAt` converts offsetless input in the job timezone. Invalid dates, gaps
  and ambiguous offsetless folds are rejected; explicit offsets identify either
  fold instant. `normalizeAt` returns schedule plus ISO confirmation data with an
  explicit job-zone offset; it sends nothing. Accepted second precision, optional
  1..3 fractional digits, one-minute grace and 365.25-day ten-year bounds remain.
- `every` retains fixed UTC anchor arithmetic across transitions. Public clocks
  remain nonnegative integer milliseconds in Date range. Before-epoch raw
  historical results are filtered at the public recovery boundary.
