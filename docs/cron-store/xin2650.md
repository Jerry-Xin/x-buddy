## Contract and API

R8 source: XIN-2050 comment `709cfb70-e0aa-49e2-8163-d4a4142abc1e`.
Full comment UTF-8 SHA256:
`c40ff6b67f2f32c28b7a57bba8605c2204212497ae0001cfc064c2e875b753a0`.
The two cron tables and six explicit indexes are verbatim section 3.4.1;
`schema.sql` SHA256 is
`7e9c38c1a53b5e0eef02531593dd9eab4afaf52e31db952d5d088bb22e229322`.
The separate bot-incarnation schema belongs to the host and is not installed.
No schema migration history, host schema or manifest is changed.

`initializeCronSchema(db)` is an explicit standalone operation. It validates
existing named objects before creating missing cron objects, refuses a changed
definition, and commits the schema in one immediate transaction. It neither
opens a database nor runs automatically in the store constructor. Future schema
extensions require a separately reviewed migration; no coercive repair occurs.

`new CronStore(db, clock)` takes the synchronous adapter shape and an explicit
`clock.now()`; it owns neither connection nor timers. Native better-sqlite3 and
the existing adapter both satisfy the structural interface. Each write owns one
`BEGIN IMMEDIATE` transaction and rejects an existing caller transaction without
committing or rolling it back. SQLite busy and integrity errors propagate.

- `create(input)` validates and normalizes a complete definition. IDs are supplied
  by the caller, must follow the R8 alphabet, and cannot reuse tombstones or IDs
  present in retained receipts. Collision retry/allocation belongs to management.
- `get`, `list`, `definition` and `dueCandidates` require an explicit conversation
  scope, or an explicit all-conversation scope already authorized by the caller.
  These selectors provide no authentication. Foreign mutations look absent.
- `edit(scope,id,expectedGeneration,patch)`, `enable`, `disable` and `tombstone`
  compare the current generation inside the transaction. Every accepted mutation,
  including a repeated enable/disable request, advances it exactly once, sets
  activation to the supplied clock and resets the watermark to NULL. A stale
  generation changes no rows. Generation exhaustion fails closed.
- Enabling resets all four failure/skip counters and auto-disable reason/time;
  ordinary edits preserve informational outcomes and counters. Disabled and
  tombstoned definitions have no next candidate. Recurring candidates use the
  accepted effective-slot helpers, including resolved stagger width. At candidates
  retain their authored time, including the accepted one-minute past-input window.
- IDs, creator, target, creation time, payload kind and delete-after-run choice
  cannot be changed through edit. Unknown fields are rejected instead of silently
  dropped. Per-job model/effort require isolated mode; timeout is 10–7200 seconds.
  Payload text accepts at most 4000 Unicode characters.

Wire `schedule_json` and `payload_json` follow R8 section 5's tagged schemas.
Cron wire data contains resolved width and timezone, without the calculation
helper's jobId or normalization-only exact flag. `definition()` returns a deeply
frozen schema-version-1 definition component. **It is not an admission receipt**:
the future admission transaction must add policy, occurrence identity, ownership,
admitted enablement/cadence and reset/owner provenance to produce R8's complete
`definition_snapshot_json`. Tests roundtrip a complete synthetic R8 receipt through
SQLite and verify that editing a running definition preserves every receipt byte.
No production receipt writer or finalizer is introduced here.

`dueCandidates` is a bounded, ordered database lookup: enabled, untombstoned,
non-NULL next candidate at or before the explicitly supplied observation time.
It does not reserve, consume, change a watermark, create overlap receipts or
authorize a run. Admission must still check effective activation, current
generation, durable watermark, provenance, authority, single-flight and backoff.
In particular, a candidate alone cannot authorize an overdue at after a new
activation domain. No automatic schedule-error/disable or recovery policy is
fabricated from an empty calculation result.
