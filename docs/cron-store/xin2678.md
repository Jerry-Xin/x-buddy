`CronStore.finalize(scope, jobId, request)` is a synchronous, short SQLite store
operation. The caller already holds the bot ownership lock. It supplies a
synchronous `ownership.assertHeld` proof and `terminalExpectation(admittedRun)`;
that expectation captures status, owner, reset generation and all immutable
admitted identity/snapshot fields. It must come from the receipt, including its
original generation and policy, rather than from a later edited job. This API
does not acquire a lock, authenticate a caller, start execution or perform sends.

## Exact request/outcome matrix

All supported entries require valid stored lifecycle and immutable provenance,
attempt0, no started/partial/uncertain delivery, zero segments, unpublished
history, and no already recorded execution failure/completion. Unsupported
outcome requests stop before the CAS. Malformed stored provenance is an
actionable `StoreIntegrityError` requesting quarantine, with no mutation.

| Request / stored state | Result and same-transaction effects |
| --- | --- |
| `success`, running/executing or delivering, admitted `deliveryMode=none`, `deliveryState=not-requested` | `ok/succeeded`; `history_state=skipped_not_requested`; no publication |
| `success`, running/executing or delivering, admitted `deliveryMode=announce`, `deliveryState=suppressed` | `ok/succeeded`; `history_state=skipped_suppressed`; no publication |
| `neutral` with `stopped`, `reset`, `reload` or `shutdown`, queued | `skipped`, NULL completion, same reason; consumes its valid current-generation reserved base without error/target/skipped counter changes or retries |
| Same neutral request, running/admission, executing or delivering without a send fence | `interrupted`, NULL completion, same reason; same neutral authored policy |
| Current, untombstoned consume attempt0, any supported outcome and any admitted consuming trigger | NULL-safe max-W in the same transaction, regardless of scheduled/catchup/manual trigger; effective recurring cadence never moves backward |
| Current consume success | Resets execution errors, skipped and target failures; schedule evaluation errors, alert state and unrelated fields remain unchanged |
| Current consuming one-shot success, `deleteAfterRun=true` | W and terminal receipt commit before an owner/generation-fenced job tombstone in the same transaction; receipt/provenance/W retained |
| Current consuming one-shot success, `deleteAfterRun=false` | Terminal disabled retained job, NULL next run, W retained |
| Current consuming one-shot neutral | Terminal disabled retained job, NULL next run, W retained; no success deletion or counter changes |
| Borrow/none, stale generation, tombstoned or missing job, supported outcome | Own receipt only, plus strictly newer informational `last_*` if the job exists; no authored W/cadence/counter/enable/delete/retry/alert effects |
| Matching already terminal receipt | Frozen `existing` stored outcome, no writes, even if the repeated outcome request differs |
| Missing receipt, wrong expected status/owner/immutable identity, wrong held owner | Frozen explicit `miss`, no effects; foreign scope is rejected |
| Attempt1..3, including a retained valid base chain | Typed `deferred: retry-chain`, no writes; chain continuation is not implemented |
| Error, target failure, restart, session-busy, retry-superseded requests | Typed `deferred: outcome-policy`, no writes; no partial terminalization before unreached retry/backoff/disable/alert policy |

Derived one-shot terminal disabling/tombstoning retains the consumed generation
and its watermark. It is not an operator edit creating a new watermark domain.
Operator edits retain the existing monotonic generation rules. No job or receipt
is hard-deleted here, and retained IDs cannot be reused.

## Transaction and provenance

Inside `BEGIN IMMEDIATE`, the store asserts held ownership, re-reads the receipt
and current definition and validates the admitted snapshot independently of a
replacement definition. Consume requires enabled-at-admission canonical effective
slot/occurrence provenance, scheduled_for=authored_slot, admission at/after that
slot, and correct manual/timed identity. Consuming manual overdue at modes and
recurring manual --due use exactly the same base predicate. Borrowed future at
uses a separate manual UUID and keeps its canonical referenced authored slot;
recurring borrow/none has no authored slot. Neither changes ownership when time
crosses the authored date. Bad consume provenance is never converted to borrow.

One UPDATE CAS checks exact expected queued/running status and every admitted
identity field, including owner, reset generation and snapshot bytes. Only one
changed row authorizes `projectTerminal`. Both this CAS path and the existing
overlap INSERT call that single shared authored writer, using
`currentDefinition/validConsume/baseConsume` predicates. Duplicates/misses never
call it. Job projection must match the re-read generation/tombstone and affect
exactly one row; otherwise everything rolls back.

The shared SQL uses `CASE WHEN last_slot_watermark IS NULL THEN S ELSE
MAX(last_slot_watermark,S) END`. Recurring next is effective next strictly after
max(ended_at,S), retaining an already later next_run_at. A lower reserved slot
succeeding after a later overlap resets its own success counters, including
skipped, without lowering W/cadence. Informational fields change only when
ended_at is strictly newer than last_run_at. One-shot retirement additionally
checks the just-terminalized receipt owner/generation and absence of active work.
An old edited-away/back callback cannot delete its replacement.

Final ownership assertion occurs immediately before commit. Synchronous fault
seams after CAS and after all projection/retirement effects prove full rollback.
No terminal current base receipt can commit separately from its W. The store
rejects caller-managed transactions and asynchronous lock/fault callbacks.
