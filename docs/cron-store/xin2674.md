## Product behavior

`CronStore.admitBase` now returns `{kind:'overlap',run}` for a newly eligible
recurring base slot blocked by other queued/running work. The caller supplies
already validated authority and a synchronous held-ownership proof; the store
does not acquire ownership or establish authority itself. Under BEGIN IMMEDIATE,
the existing current-generation, definition, authority, canonical receipt and
effective-slot checks run before fresh watermark/cadence/single-flight eligibility.
A matching receipt returns its exact stored reservation/outcome. An absent slot
at/below W returns already-consumed. Neither repeats any effects.

A new overlap is inserted directly as skipped(overlap), never queued/running.
Every RunRow column is explicitly supplied: consume/canonical attempt0 and
immutable definition/policy/admission/owner/reset provenance; authored_slot,
scheduled_for and ready_at equal S; phase/completion/start/thread/turn/model/usage
are NULL; not-requested delivery, zero segments, not-published history;
queued_at=ended_at=observedNow. The other active receipt remains byte identical,
including an older generation's running owner or a retained retry chain.

Only INSERT ... ON CONFLICT(occurrence_id,attempt) DO NOTHING RETURNING run_id
returning a new row authorizes the projection. Unrelated constraints and invalid
retained provenance raise StoreIntegrityError. The new terminal projection shares
named currentDefinition/validConsume/baseConsume predicates: validConsume checks
the immutable canonical effective authored identity and admitted snapshot;
baseConsume adds current untombstoned generation and attempt0. These predicates
are separate from terminal entry and from future retry-chain validation.

The same transaction applies NULL-safe max(W,S), one skipped increment, natural
effective next strictly after max(observedNow,S), and retains a later stored
next_run_at. Its generation/non-tombstone UPDATE must affect exactly one row.
Informational last_* fields change only if observedNow is strictly newer than
last_run_at (or last_run_at is empty); equal timestamps retain the stored outcome.
Error/target/schedule counters, enablement, alerts and history are untouched.
The held-ownership assertion runs again immediately before commit. Any fault,
constraint, predicate miss or lost ownership rolls back the receipt and effects.

Merely queued retries retain the distinct no-write queued-retry-supersession
deferral. Authored at slots blocked by a borrower retain one-shot-busy with the
original slot/W/cadence and a 30000ms recheck result. This library introduces no
scheduler wake/timer, execution permit, model call, turn, retry or send.
