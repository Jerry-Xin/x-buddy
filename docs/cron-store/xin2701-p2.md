The previous execution replay path validated immutable provenance and retained

timing, CAS, W, counters and cadence mechanisms remain unchanged.

## Consistency boundary

| Stored facts | Required representation |
| --- | --- |
| Queued/running | No terminal completion/reason/error or terminal publication disposition. No-send states have zero segments; actual delivery activity requires delivering phase. Queued delivery remains not-started with zero segments. |
| Terminal ok/succeeded | Delivery is not-requested, suppressed or confirmed delivered; no failure reason/error; success respects admitted none versus announce policy. |
| Terminal ok/failed | Delivery is not-delivered, with skipped_not_delivered history. This preserves target-only failure. |
| Terminal ok/unknown | Delivery is unknown, with skipped_not_delivered history; no fabricated publication. |
| Terminal error | Completion failed, no-result delivery not-requested/suppressed and matching history. |
| Skipped/neutral interrupted | NULL completion and not-requested/suppressed delivery with matching history. Valid nullable-start session-busy skips remain supported by the unchanged provenance/chain validators. |
| Interrupted restart with ambiguous delivery | Unknown completion/delivery and skipped_not_delivered history remain representable under R8 M2-10. Restart production is not implemented here. |
| Confirmed delivered | Positive segment evidence and a R8 publication disposition: published, skipped_reset or skipped_session_mode. This checks receipt consistency, not actual remote delivery or host publication rows. |
| Not-requested / suppressed | Zero sent segments and skipped_not_requested / skipped_suppressed history. Missing result delivery in these deliberate no-send outcomes remains valid. |
| Direct-terminal overlap | R8's explicit skipped/NULL-completion/not-requested/zero-segment/not-published/no-start exception remains distinct. |

The audit inspected every existing-result return in the store. New execution
replay and terminal outcome replay now share this validator. Legacy `admitBase`
reservation replay retains its accepted metadata contract and historical fixture
expectations; it never grants execution permission. Simple get/list reads are
not new integrity or authorization gates. The active finalizer's existing typed
unsupported-state deferrals remain unchanged, including pending completion/error
and publication facts. This avoids silently replacing approved no-write outcome
policy with a new finalization or repair workflow.
