## API and trust boundary

`admitBase` remains reservation-only. The additive public methods are:

```ts
store.startBase(scope, jobId, request: ExecutionAdmissionRequest);
store.admitRetry(scope, jobId, request: ExecutionAdmissionRequest);
```

The original `admitRetry(scope, jobId, runId, ownership)` keeps its exact
`{kind:'deferred',reason:'retry-admission'}` no-write result. None of the old
unsupported assertions or1173 retained cases was changed or dropped.

The new envelope carries an exact queued `TerminalExpectation`, the existing
`AdmissionAuthority` and ownership proof, plus grant time, fixed absolute
admission deadline, runtime generation and issuer-bound proof handle. The
store captures/freeze-copies the data before use. Unknown fields, accessors,
incomplete identity and malformed values are rejected. Missing authority or
proof bindings defer without writes. The original caller object cannot
change the snapshot used by validation/CAS.

**Production defaults to no permission.** The constructor's optional fourth
argument is an internal typed `ExecutionAdmissionVerifier`; no production
issuer, issuer factory or host wiring is supplied. With no verifier, every
new execution entry returns a typed no-write deferral. The request's
`executionProof.assertCurrent` is an issuer-bound handle only: the store never
calls it or treats its presence/return value as verification. Booleans in
`AdmissionAuthority` cannot authenticate a request either.

The separately configured verifier must recognize/bind the complete frozen
envelope, finishing external resolution in `prepare` **before BEGIN**. An
unrecognized/unavailable grant returns undefined. A recognized grant yields
a synchronous guard checked under the SQLite write lock at entry and again
before commit. A Promise from preparation or a guard is rejected. Configuring
this internal port is trusted integration work, not a request-selected option.
The only issuer implementation in this change is the explicitly labeled,
stateful **test** fixture in `test/cron-store/execution-fixture.mjs`. Production
source imports no test fixture and has no permissive fallback or proof cast.

A future reviewed production issuer must independently verify current creator
authority and target access under existing R8 rules; admitted policy remains
permitted without widening; actual held owner/reset lineage; a held per-bot
permit for the exact receipt/attempt; effective `cron.admissionWaitMs` and its
original grant-derived deadline; current runtime generation, usable exclusive
lane, session lock/completion barrier where applicable, and abort/shutdown/
quarantine state. Its freshness guarantee must span the synchronous transaction.
This increment supplies no evidence of real membership, permits, lanes or RPCs.
Unbound reset semantics remain unsupported; no owner adoption/recovery or reset
policy is inferred from equal request numbers. R8's isolated reset/publication
exception remains the future issuer/publication owner's responsibility.

## Transaction and outcomes

The shared path rejects caller nesting and uses short synchronous BEGIN
IMMEDIATE. It re-reads the scoped job, exact candidate, canonical attempt0 and
all predecessors, using the accepted provenance/lifecycle/chain validators.
Queued receipts must have clean NULL execution/publication metadata, zero
segments and not-started delivery. Current enabled/nondeleted generation,
effective authored slot and activation, exact authority/definition/policy,
captured owner/reset, unique occurrence/attempt and sole active candidate are
required. The candidate satisfies single-flight itself; it is not an overlap.

Retries require consume ownership, trigger retry, attempt1..3, contiguous
retryable retained predecessors with exact Q/busy timing, and committed base
W>=S. The P2 fix is retained for every executed predecessor: start/end evidence,
cleared terminal phase and ready/start/end order. Valid nullable-start
session-busy skips remain valid. Mixed old-owner chains are refused pending
separately validated recovery. A reserved base behind a later overlap W remains
distinct from a forbidden new attempt0: this path never re-reserves a slot.

Eligibility requires `now>=max(queued_at,ready_at,permitGrantedAtMs)` and
`now<admissionDeadlineMs`. The grant/deadline difference must fit R8's
1000..1800000ms admission-wait bounds; the issuer must bind it to the actual
effective configuration. The store never substitutes ready_at, execution
timeout or a freshly renewed budget. A recurring retry at/after the first
natural effective slot after its predecessor requires OD-39 supersession and
defers before CAS. One-shot retries preserve the original authored slot.

One exact expected status/owner/provenance/clean-lifecycle CAS sets only
`status=running,phase=executing,started_at=now` on the retained row. Exactly one
changed row is required. No INSERT, new attempt0, W, counters, cadence, permit
acquisition/release or external dispatch occurs. Precommit rechecks ownership,
trusted proof, fresh clock/deadline/priority, the complete current job and
retained chain plus the exact resulting receipt. Loss/fault after CAS rolls
back all attempted writes. The stored result is frozen.

| Condition | Result / effects |
| --- | --- |
| New eligible validated CAS | `admitted`, with frozen running/executing receipt; one receipt UPDATE only. |
| Matching running/terminal duplicate | `existing`, frozen stored data; no second dispatch permission, timestamp reset, deadline renewal or DML. The stored lifecycle and full retained chain are checked before return. |
| Foreign/stale expected identity or captured owner/reset | `miss`, optionally scoped stored row; zero DML. |
| Missing proof/authority fields | `deferred/execution-admission` for base or `deferred/retry-admission`, prerequisite proof-missing; zero DML. |
| Absent issuer or unknown/unbound handle | Same deferral with issuer-unavailable; zero DML. Arbitrary request no-ops/booleans cannot grant admission. |
| Before ready/queue time or outside original grant/deadline | Same deferral with not-ready / permit-not-current; zero DML. Deadline equality is expired. |
| Recurring natural-slot priority reached | `deferred/queued-retry-supersession`, activeRunId and30000ms recheck; zero DML. No supersession or skip is persisted. |
| Disabled/stale generation, mismatched current authority/policy, wrong admission kind or borrow/none | `StoreConflict`, zero DML. |
| Missing/out-of-scope/deleted queued job | `JobNotFound`, zero DML; no receipt existence disclosure. Terminal duplicate data remains replayable after derived one-shot retirement. |
| Invalid lifecycle/base/chain/W/activation | `StoreIntegrityError` with quarantine requirement, zero validation-path DML. No repair or alternative attempt is manufactured. |
| Malformed request / asynchronous guard | Existing TypeError/RangeError validation; no grant. |
| Contention, entry/precommit proof loss or CAS miss | Error/rollback. After-CAS faults may attempt DML; they leave zero committed changes. A caller retry must re-read/revalidate. |

Only a newly returned `admitted` result can permit one caller dispatch, after
commit. `running/executing` and started_at record store execution entry; they
do **not** assert that turn/start was accepted. Actual execution budget still
starts at accepted turn/start. Crash after admission commit but before dispatch
is not an atomic external-execution guarantee. Recovery/old-child termination
must be supplied separately; `existing` never authorizes replay.
