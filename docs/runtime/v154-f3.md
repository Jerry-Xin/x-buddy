This correction continues exact parent
`325da9f382c9ef073c4cf8bd4277586fc6609ba9`. Its persistence binding already
latched failures, but the SDK executor consumed that guard only at construction.
The unchanged bridge can swallow a session callback failure and classify its
diagnostic text as a stale thread. A rejected durable resume clear could therefore
enter a fresh SDK driver; a stale-worded mapping rejection could replay accepted
work.

methods with the same constructor-bound turn guard. Start/resume, every
`runStreamed`, iterable acquisition and the first lazy iterator pull consume that

its driver. Return/throw forwarding preserves the original iterator receiver and
does not require renewed permission to collect it. An already entered driver is
collected normally; the bridge retains its existing effect/publication checks.
No SDK work is retracted or replayed and no error-text authorization is added.
Valid one-time pre-turn stale-resume recovery remains available when the durable
clear commits and the canonical guard stays current.
